# Punctuation

Use this guidance for punctuation in ordinary technical prose. Preserve punctuation required by code, exact product names, quoted source text, and the surrounding document format.

## Colons

Use a colon to introduce an explanation, list, command, or description when the preceding clause is complete. Use a period instead when the material after it is a separate sentence or paragraph.

## Commas

- Use a comma after an introductory word, phrase, or clause when it improves readability.
- Use a comma before a coordinating conjunction that joins two independent clauses, except when both clauses are very short.
- Use a serial comma in a list of three or more items.
- Usually do not use a comma before `because`.
- Use a comma before `which` when it begins a nonrestrictive clause.
- Do not add commas merely to create pauses. Use sentence structure when a sentence is hard to follow.

## Dashes and hyphens

- Use an em dash only for a genuine break or interruption, without spaces. Do not use it as a list separator.
- Do not use an en dash as punctuation or as a range marker in repository prose.
- Use a hyphen for compounds and number ranges such as `5-10 minutes`.
- Hyphenate a compound modifier before a noun when needed for clarity. Usually do not hyphenate the same compound after the verb.
- Check the project convention, word list, and dictionary when compound spelling is uncertain.

## Ellipses

Use an ellipsis only when an omission itself matters. In code samples, represent omitted code with a comment in the language of the sample. Do not use an ellipsis character to make a sample look incomplete or copyable.

## Parentheses

Use parentheses for a necessary clarification or real aside. Do not use them to mark optional procedure steps, replace a heading, or hide a requirement. Use `Optional:` for optional steps.

## Periods and end punctuation

- End complete sentences with a period, including list items that are sentences.
- Omit end punctuation for a single word, a noun phrase without a verb, an all-code item, or an all-link item. Keep punctuation consistent within a list.
- Do not use exclamation marks in normal technical prose. Use a period or rewrite the sentence.
- Do not use punctuation merely to create dramatic emphasis.

## Quotation marks

- Use straight quotation marks in new Markdown prose unless the document format requires another form.
- Use quotation marks for short works and direct quotations. Use italics for standalone works unless the title is part of a link.
- Put punctuation outside link text and follow American punctuation rules for quotations.
- Preserve quotation marks exactly when reproducing source text or a literal value.

## Semicolons

Use a semicolon only when it makes the relationship between two closely related independent clauses clearer. Prefer a period when separate sentences are easier to scan.

## Slashes

Avoid slash constructions when an explicit phrase is clearer. Replace `and/or` with the actual alternatives. Preserve slashes in technical syntax, URLs, paths, dates, units, established names, and space-constrained tables when they carry real meaning.

## Review checklist

- [ ] Colons introduce complete explanations, lists, commands, or descriptions.
- [ ] Commas clarify grammar without creating arbitrary pauses.
- [ ] Dashes, hyphens, and ranges follow the intended meaning.
- [ ] Ellipses appear only when omission matters.
- [ ] Parentheses contain necessary asides, not hidden instructions.
- [ ] End punctuation is consistent and non-dramatic.
- [ ] Quotes, semicolons, and slashes are necessary and correctly formatted.
