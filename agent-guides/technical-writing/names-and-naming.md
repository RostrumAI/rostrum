# Names and naming

Use this guidance for product names, filenames, example data, domains, identifiers, and trademarks.

## Product and feature names

- Preserve the official spelling and capitalization of products, organizations, APIs, languages, libraries, and UI labels.
- Do not capitalize an ordinary feature name unless its official name requires it.
- Do not use a product or feature name as a verb unless the product documentation explicitly does so.
- Do not add `the` before a product name unless grammar requires it for a noun phrase.
- Use code font for code identifiers and ordinary text for product names unless the product is being shown as literal input.

## Filenames and identifiers

Use the repository's established filename and identifier conventions. Format filenames, paths, extensions, and literal names as code. Show the exact case when case matters. Do not invent a casing-style requirement such as “use camel case”; state the actual pattern and give an example.

## Example domains and data

Do not use real personal or organizational data. Use `example.com`, `example.org`, or `example.net` for generic domains. Use fictional names, reserved US phone numbers, RFC 5737 IPv4 ranges, and RFC 3849 IPv6 ranges. Prefer meaningful project names such as `staging`, `frontend-development`, or `production-1` over `foo`, `bar`, or `baz`.

Choose examples that do not assign stereotypes to names, jobs, regions, or technical roles. See `inclusive-and-global-language.md` for broader example guidance.

## Trademarks

Preserve the official spelling of trademarks and product names. Do not turn a trademark into a generic verb or noun. Follow the owning organization's documented usage when a trademark or attribution requirement applies. Do not add legal claims or trademark notices unless the document or project requires them.

## Review checklist

- [ ] Product names, trademarks, filenames, paths, and identifiers match their authoritative spelling.
- [ ] Code names use code formatting and exact case where required.
- [ ] Example data is fictional, reserved, meaningful, and non-stereotyped.
- [ ] Casing requirements describe actual patterns rather than style labels.
- [ ] Product names are not used as generic verbs or nouns.

Sources: [Product names](https://developers.google.com/style/product-names), [Example domains and names](https://developers.google.com/style/examples), [Filenames and file types](https://developers.google.com/style/filenames), and [Trademarks](https://developers.google.com/style/trademarks).
