# Links and cross-references

Use this guidance when adding or reviewing links, references, and navigation between documents.

## Rules

- Provide enough context on the current page for a basic definition or a short procedure.
- Link selectively. Each link adds a decision and can interrupt the reader.
- Link to the most relevant page or section, not a generic home page.
- Avoid duplicate links to the same destination within a page unless the links serve clearly separate entry points.
- Use short, unique, descriptive link text that makes sense out of context.
- Do not use `click here`, `this document`, `this article`, `read more`, or a raw URL as link text.
- Include a long form and abbreviation together in link text when the sentence introduces both.
- Include the description of a command, flag, method, or API when linking it.
- Use `For more information, see ...` or `For more information about ..., see ...` for dedicated cross-reference sentences.
- Use `about`, not `on`, when describing the linked subject.
- Put punctuation outside link text.
- Use site-root-relative URLs for internal links when the documentation system supports them and HTTPS for external links.
- Explain unexpected behavior such as downloads, email links, new tabs, or jumps to another section.
- When linking to a heading, use a stable, descriptive heading that can serve as a useful link target. Do not make a heading a link merely for visual styling.

## Review checklist

- [ ] The link text identifies the destination without surrounding prose.
- [ ] The page provides necessary context instead of outsourcing basic explanation.
- [ ] The destination is specific and relevant.
- [ ] Duplicate and vague links are removed.
- [ ] Unexpected link behavior is clear.

Sources: [Google Cross-references and linking](https://developers.google.com/style/cross-references) and [Headings as link targets](https://developers.google.com/style/headings-targets).
