# Terminology

Use this guidance when a word, abbreviation, product name, code identifier, or technical term is unfamiliar, overloaded, disputed, or inconsistent across documents.

## Rules

- Consult the [Google word list](https://developers.google.com/style/word-list) for unfamiliar, inclusive, product, and technical terms.
- Follow project-specific terminology before general guidance.
- Prefer a precise term over a broad word such as `support`, `solution`, `workload`, `agnostic`, or `actionable`.
- Define an abbreviation on first use when readers might not know it or when it is infrequent or ambiguous.
- Preserve exact product names, API names, code identifiers, keywords, and legal terms when accuracy requires them.
- Do not use product or feature names as verbs unless the product documentation explicitly does so.
- Use American English spelling unless a project, product, or code convention requires another form.
- Keep one term for one concept. Do not cycle synonyms for stylistic variety.
- When a word-list entry says `Don't use`, replace it or rewrite around it. When it says `Use with caution`, prefer a more precise term and define the word if it remains necessary.

## Rostrum terms

- Use `workflow`, not `mode`, for a unit that defines and executes behavior.
- Use music-related names only when their meaning is immediately clear.
- Do not describe prompt intake, workflow selection, or AI authorship as inherent platform behavior. Describe them as capabilities a workflow may implement.

## Review checklist

- [ ] Product, API, and code names match their official spelling.
- [ ] Abbreviations are defined when needed.
- [ ] Terms are consistent across the document and neighboring documents.
- [ ] Word-list cautions have been resolved with a precise alternative or explanation.
- [ ] Rostrum vocabulary matches the Rostrum-specific section in `skills/technical-writing-core/SKILL.md`.

Source: [Google Word list](https://developers.google.com/style/word-list), [Product names](https://developers.google.com/style/product-names), and the Rostrum-specific section in `skills/technical-writing-core/SKILL.md`.
